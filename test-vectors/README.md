# BEEF golden vectors — TS-generated, normative

Cross-language conformance corpus for BEEF (BRC-62), BUMP (BRC-74),
Atomic BEEF (BRC-95) and BEEF V2/txid-only (BRC-96). **Generated by the
TypeScript `@bsv/sdk` (v2.3.1), which is the normative reference** — every
`expected_*` field is byte-exact TS output. Rust (`bsv-sdk`,
`rust-wallet-toolbox`) and Go consumers assert equality against these bytes;
where a consumer disagrees with a vector, the consumer is wrong.

| file | pins |
|---|---|
| `beef_atomic_closure.json` | `toBinaryAtomic` — BRC-95 dependency closure, unsorted inputs, unrelated-tx dropping, bump pruning |
| `beef_sort_order.json` | `sortTxs()` ordering + `SortResult` fields; post-sort `toBinary` bytes |
| `beef_invalid.json` | negative corpus — each case carries the expected rejecting rule (NOTE: TS `verifyValid` ACCEPTS trailing garbage; recorded as truth in `SURPRISES.json`) |
| `beef_merge.json` | merge semantics — full-tx vs txid-only precedence, bump dedup by (height, root), index re-derivation. **Compare STRUCTURALLY, not byte-equal** (see `SURPRISES.json`) |
| `beef_spend_closure.json` | the rust-mpc#352 regression shape — a caller-named input's parent MUST ride in the child's Atomic BEEF |
| `rust_advert_verify.mjs` | the Rust-built → TS-verified half (R6b residual): pipe any emitted BEEF hex through the normative verifier |
| `generator/` | the vendored deterministic generator (no Date/random; fixed keys) — rerun against a newer @bsv/sdk to regenerate |

`SURPRISES.json` records where TS behavior diverged from naive spec reading —
those entries are parity notes for implementers, not defects to "fix".
