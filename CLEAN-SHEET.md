## 1. The headline: TS ↔ Rust certificate exchange was impossible. It now works.

Before this branch, `AuthMessage.certificates` was typed `Vec<Certificate>`, which has no `keyring`
field. TypeScript signs `JSON.stringify(certificates)` over `VerifiableCertificate`, which carries the
keyring. **The two languages computed different signing preimages, so certificate exchange failed in
both directions.** Every test in the repo was Rust↔Rust with an empty keyring, so nothing caught it.

| | |
|---|---|
| **Fix** | `types.rs` carries `VerifiableCertificate` end-to-end; `keyring` is an `IndexMap` |
| **Why `IndexMap`** | `HashMap` iteration order is randomized, so a certificate revealing >1 field produced a *different preimage on every run* — intermittent signature failures, not a clean red |
| **Proof** | Cross-language vectors generated by real `@bsv/sdk` 2.4.1 (generator asserts name and version): Rust reproduces the TS preimage **byte-for-byte** and verifies TS signatures; Node verifies Rust signatures |
| **Mutation** | Dropping `keyring` from serialization turns all 3 interop tests red |
| **Independent check** | A separate vector I generated from real TS *before this code existed* — re-run after every round, still byte-exact including keyring ordering |

## 3. Concurrency: rebuilt on Go's granularity

The original port dispatched **one task per inbound message**, bounded by a global semaphore of 64 and a
per-session sub-quota of 8. That granularity was the root of a five-cycle defect chain: a
certificate-gated message parks up to 30s *holding a dispatch permit*, so one peer could occupy every
slot. Three attempts to bound it (per-session quota, a 7-session cap, an identity quota) each produced a
new defect — the 7-session cap allowed a **cheaper** denial than the one it prevented, and hard-capped
honest servers at 7 concurrent handshakes.

**Now: one sequential worker per session** — Go's model (one worker per connection, sequential within
it), with the certificate gate retained. Both semaphores deleted.

The non-obvious part: Go has **no certificate gate**, so the model does not transplant directly. If a
worker parked on a gated frame also had to process that session's own `certificateResponse`, the
deadlock returns. **Control frames bypass the session workers** — this is load-bearing, and pinned by a
deterministic assertion enumerating all four control types.

| Property | How it's proven |
|---|---|
| Deadlock cannot return | Routing `certificateResponse` through the worker turns **4 tests red in 7.51s** — fails, does not hang |
| One session cannot starve another | Structural: separate workers, no shared dispatch resource |
| Same-session ordering guaranteed | New property — the old design did **not** guarantee it |
| Replay marked exactly once | Holds across worker restart, overflow drops, and eviction |
| Session cap (1024) doesn't refuse honest traffic | Legitimate handshake succeeds at the cap; LRU eviction is deterministic and mutation-proven |

Also fixed: `validate_certificates` now runs bounded-concurrent (10 certs: **1s → 200ms**), matching Go's
`NumCPU`-bounded worker pool. `prove_certificate` deliberately stays sequential — Go's judgement outweighs
TS's `Promise.all`, which in a single-threaded runtime is interleaved I/O, not parallelism.

This class recurred more than any other, and **three instances were introduced by fixes for earlier
instances**.

| # | Site | Status |
|---|---|---|
| 1 | `keyring` as `HashMap` in a signed preimage | Fixed |
| 2 | `decrypted_fields` as `HashMap` in a signed preimage | Fixed — the ledger had certified it MATCH against a **one-key** fixture, which is deterministic for any map |
| 3 | `master.rs` issuance discarded caller field order | Fixed |

| 5 | `signable_request_headers`: `HashMap` + lowercasing + *stable* sort → preimage differed run to run | Fixed by rejecting duplicate case-insensitive headers — a `HashMap` cannot represent TS's insertion-order behaviour, so the bad state is now unrepresentable |

## 6. Known gaps — deliberately not fixed

**Non-ASCII certificate field names produce a different signing preimage than TS.** Verified by running
2.4.1: TS orders `aaaa, éééé, tag_A, tag-A, zzzz`; Rust puts all non-ASCII last. Field validation permits
any 1–50 characters, so it is reachable. **Fail-closed** — cross-SDK verification fails rather than
accepting something wrong — and no real issuance path uses such names. Not rewritten because the
comparator is pinned against 401 Node-generated ASCII vectors. Registered in the charter.

**Per-identity fairness is not enforced.** Identity keys and sessions are both free to mint, so there is
no scarce key to quota against. Per-*session* isolation is now structural. TS is unbounded here; Go has
no gate.

**Conformance corpus coverage is 266 of 1,565 non-script upstream vectors (17%).** The certificate and
auth surfaces we touched are covered; wallet, overlay and broadcast largely are not. "Verified
byte-compatible" is true of certificate exchange, **not** of the whole SDK.

## 7. Breaking changes — downstream must move together

- `AuthMessage.certificates`: `Vec<Certificate>` → `Vec<VerifiableCertificate>` (**wire format**)
- `Peer::on_certificates()` removed → `listen_for_certificates_received`
- `Peer::process_next` / `process_pending` removed → background receive task
- `Peer::on_error()` added; `Peer` is cloneable; `Peer::new` requires a Tokio runtime
- `SessionManager::update_session` returns `bool`

`0.8.0`, not `0.7.2`: a patch bump would auto-propagate a wire break to anything pinned `^0.7`.
